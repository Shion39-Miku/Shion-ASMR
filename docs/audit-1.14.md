# 月咲 Shion 1.14.0 检查记录

本轮从 1.13.0 发行版及其源码建立基线，再使用 1.14.0 便携 ZIP 解压后的程序验收。演示用音轨、字幕、图片和视频来自合成素材。回归使用独立配置目录。

## 复现与修复

| 复现步骤 | 旧版表现及原因 | 修复后的行为 |
| --- | --- | --- |
| 播放一首音轨，再打开损坏的 WAV | 旧播放设备先释放，读取新文件失败后会话已丢失 | 新解码器和输出设备就绪后才切换，失败时保留原会话与字幕 |
| 播放目录中的文件，随后在媒体目录管理中移除该目录 | 磁盘索引还包含旧目录，续听候选仅检查文件是否存在 | 保存目录变更后梳理索引，续听只使用已登记、已索引且存在的文件 |
| 在播放器退出期间向已导入目录添加媒体，再启动 | 已有索引时启动流程跳过增量扫描 | 主页就绪后后台复核目录。无变化时跳过索引写盘与分类重建，暂时离线的根目录保留原索引 |
| 打开包含大量系列的社团，再返回并滚动 | 分类反复查找同一批作品的祖先，小幅连续滚轮输入会拖长动画 | 后台一次汇总各子分类的归属和代表封面。滚轮反向立即换目标，收尾后停止绘制 |
| 在窄窗口开启分类文件夹树，从快捷入口进入深层系列 | 固定高度的社团栏压缩文件夹树。「返回上一级」可能回到较早访问的目录 | 两个列表按可用高度分配空间。「返回上一级」走真实父目录，从作品返回继续保留浏览历史 |
| 播放时同时开启星空、樱花、波形和字幕，快速切换页面 | 星空和波形逐帧触发布局失效，过渡中断时透明度容易回到初始值，字幕重复合成相同字符串 | 固定星云与动态绘制分离，当前动态画布直接刷新。过渡从当前可见位置衔接，字幕正文只在台词变化或需要刷新时更新 |
| 播放时翻到图集第二张，随后刷新目录 | 图片发现结果每次把图集重置到第一张，旧请求完成后还可能提交显示更新 | 同一媒体刷新时保留仍存在的图片，切换媒体按自然排序从首张开始，过时结果停止更新 |

分类空状态提示可清除筛选或更换关键词。底栏的播放模式在宽窗口显示更完整，名称在窄窗口可悬停查看。分类统计和底栏格式信息也支持完整悬停提示。

## 测量方法

环境为 Windows 10 22H2（19045）、Intel Core i7-12700（20 个逻辑处理器）、GeForce RTX 2080 Ti 与 WPF 渲染等级 2。对照使用同一桌面环境。分类测试包含 1,154 部生成的作品和 36 个系列，切换 14 次并改变列表滚动位置。播放测试使用真实 WAV 解码，保持同步字幕、星空、樱花与音频波形开启。

测试以 Stopwatch 采集 WPF 合成回调间隔，并统计星空与波形提交绘制命令的次数及间隔。CPU 按全部逻辑处理器容量计，内存分别记录工作集和私有字节。绘制命令计数用于检查程序的调度，设备呈现帧率需另行测量。

带缓存启动分别测量三次，从启动便携程序的运行进程到主页就绪信号。1.13.0 中位数为 996 ms，1.14.0 为 978 ms。测量以约 20 ms 的间隔读取就绪信号，两版均约 1 秒。

| 同一桌面的演示场景 | 1.13.0 | 1.14.0 |
| --- | ---: | ---: |
| 首次导入 1,154 部作品 | 162.0 ms | 150.5 ms |
| 第二次扫描同一目录，两次均未枚举文件 | 55.5 ms | 6.0 ms |
| 14 次系列切换中最慢的一次 | 18.0 ms | 8.7 ms |
| 分类切换时 WPF 合成回调间隔 P95 | 26.4 ms | 18.1 ms |
| 分类切换时星空绘制频率 | 57.4 次/秒 | 59.8 次/秒 |
| 分类切换时 CPU / 工作集 / 私有字节 | 3.98% / 254.6 MiB / 219.4 MiB | 3.84% / 243.8 MiB / 249.7 MiB |
| 播放时星空及波形各自的绘制频率 | 59.3 次/秒 | 59.8 次/秒 |
| 播放时星空绘制间隔 P95 | 31.6 ms | 30.8 ms |
| 播放时 CPU / 工作集 / 私有字节 | 2.60% / 276.2 MiB / 225.4 MiB | 2.97% / 270.1 MiB / 233.8 MiB |

每次增量扫描仍会核对目录时间与目录结构。上述数值来自本机短测，会随磁盘、媒体库结构及系统负载变化。分类切换缩短最明显。组合播放场景仍有长帧，CPU 和私有字节也略有上升，稳定 60 FPS 仍是优化目标。

另以 2,403 部作品验证真实滚轮。在该窗口下，分类列表仅生成 3 个可见和预取网格行，封面缓存为 24 项。连续 72 次切轨和切页过程中，预热后私有字节由 267.8 MiB 增至 279.5 MiB，进程句柄由 1,174 增至 1,177。托管对象单独强制收集后取样，预热后为 13.0～14.5 MiB。该短测用于比较连续切换，持续增长情况仍需数小时运行检查。

## 发行验证

最终发行包通过 9 组共 312 项自动化检查。一轮组合验收中原生输入遇到窗口遮挡，桌面字幕工具栏与台词空档用例在同一发行包中单独复跑通过。

- 从 ZIP 解压启动，欢迎主页就绪且未自动播放。重新打开独立演示档案后恢复至 18.40 秒和保存的字幕偏移，关闭期间新增的音轨通过启动后的增量扫描进入索引。
- 实测后台扫描和社团快速切换、系列及作品返回、标签和搜索、长列表滚轮、音频进度定位、同名字幕、无字幕切换及过期请求失效。
- 验证音频台词空档保留、视频台词空档清空、暂停和恢复后的居中跟随，以及窗口内、全屏视频字幕与原生进度点击和拖动。
- 验证桌面字幕从台词和黑底空白拖动、拖边／拖角缩放、设置按钮、锁定穿透、悬停解锁及后台同步。原生输入验证包含普通桌面与模拟的窗口化、无边框窗口。
- 从 Windows WASAPI 输出回环测量生成的双声道音频，用 10%～90% 振幅估算。淡出约 508 ms，淡入约 509 ms。暂停前额外等待输出缓冲排空。隐藏主窗口时星空和波形停止，音频和桌面字幕继续运行。
- 验证便携启动器、关闭确认三种行为、系统托盘恢复及彻底退出，使用窄窗、常规窗宽及等效 100%、125%、150% 缩放检查重点界面。

实际物理混合 DPI、独占全屏游戏、GPU 呈现帧率及长时间持续播放仍需更多验证。打开无法解码的直接视频可能结束先前的音轨，本轮的失败会话保护覆盖了音轨解码。

如需复查，可在仓库根目录对解压后的 `runtime\Shion.exe` 运行 `--self-test <独立输出目录> --audit-release`。验证目录会生成演示媒体、截图、`verification.json`、`audit-summary.json` 和 `frame-performance.json`。原生输入检查可单独运行 `--revision11-only` 或 `--revision15-only`，测试期间需要桌面前台。
